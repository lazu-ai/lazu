Lazu 发出的每一封邮件都属于三层之一。层由「这封信的新闻是什么」决定，不由发信的模块决定。

## 1. 三层

| 层 | 新闻 | 邮件 |
| --- | --- | --- |
| **墨头 ink** | 一个金额或比例 | 付款到账（锁定，`payment-emails.md`）、余额调整、余额不足、Key 用量提醒、成员预算（预警 / 用完，眉行 `MEMBER BUDGET`）、项目月上限（眉行 `PROJECT BUDGET`） |
| **纸面 paper** | 账号或团队里发生的事 | 注册 / 登录验证码、欢迎、重置密码、密码已修改、账号不用密码、邮箱已注册、暂未开放注册、项目邀请、邀请明天过期、邀请过期未接受、已加入项目、成员变动（8 种）、平台通知 |
| **运维 ops** | 需要运维处理的事，只发管理员 | 磁盘、错误率、付款单据异常、Stripe 退款 / 争议、备份上传、测试邮件 |

对照：付款邮件定稿时的调研（`payment-emails.md` §1）显示同类产品没有一家把品牌大抬头用在所有邮件上；
只有钱的消息配大抬头，其余保持朴素。账号类和运维类邮件没有另做对照调研。

## 2. 共用规则

- **外框**：640px，地面 `#f2f2ef`，页脚在卡片外：左 `Lazu.ai`，右 联系支持 / Contact support。运维页脚左侧
  是 `lazu-backend@<NODE_NAME>`，右侧打开控制台。不写「系统邮件，请勿回复」「© 年份」「感谢一路相伴」。
- **标题行**：用户邮件不加 `[Lazu]` 前缀，直接说事（「Lazu 余额只剩 $3.20」「Panda 邀请你加入 北辰实验室」）。
  运维邮件统一 `[Lazu ops]` 前缀。
- **预览文字**：每封都有 preheader，写标题没说完的半句。
- **眉行**：等宽 11px、`.16em` 大写英文，不翻译：`VERIFY EMAIL`、`LOW BALANCE`、`PROJECT UPDATE`……
- **Logo**：墨头用 Primary Paper（`lazu-email-logo-paper.png`），纸面用 Primary Graphite（`lazu-email-logo.png`），
  运维不放 Logo。旧的方块标记 `lazu-email-mark.png` 退役（文件保留给已发出的旧邮件）。
- **字体**：衬线（回退 Georgia）只给墨头的金额与比例；中文标题用系统无衬线 600；编号、Key、验证码、运维值用等宽。
- **颜色**：墨 `#202329`、纸 `#fbfaf7`；长春花蓝只给验证码与次要链接；运维的 ALERT / WARN 只染那一个词
  （`#b42318` / `#b54708`）。
- **动作**：每封最多一个墨色主按钮 + 一个文字链接。墨头层的按钮上方有一条发丝线（手机上隐藏）。
- **钱**：一律 `$1,234.50`，调整额带正负号。不用全角 `＄`、不写六位小数。
- **深色**：沿用付款邮件的深色规则。

## 3. 语言

- 发给人的邮件中英各一份，按收件人在控制台最近使用的界面语言发（`users.setting.language`）。中文变体读中文，
  其余读英文；未知时读英文（2026-09-30 由中文改为英文）。
- 控制台每次请求带 `Accept-Language: <界面语言>`，切换语言时写回账户（`PUT /api/user/self/language`），首次登录时
  补记。没有账户的收件人：验证码类邮件按请求语言，项目邀请按邀请人的语言。
- 付款到账邮件按 `payment-emails.md` 保持英文。运维邮件只写中文。

## 4. 发哪些、不发哪些

2026-09-30 删减后保留的邮件见 §1。以下已删除，不得加回：

- 付款收据 + PDF 附件、管理员付款通知、待付款提醒：只属于老的个人充值流程；项目充值只发一封付款邮件。
- 「额度即将用尽」通用邮件：并入余额不足邮件；用户自己的 Webhook / Bark / Gotify 通知保留。
- 通道被停用 / 恢复：改发飞书，通道状态看健康页。
- 通道测试完成：界面上已能看到结果。
- 公告与管理员群发合成一个「平台通知」（纸面，眉行 `NOTICE`）。

后台不再提供邮件主题与模板的编辑；只保留开关（余额调整、余额不足及其提醒线与节奏）和运维收件人。
运维邮件发给 `ADMIN_EMAIL`，未配置时发给 root 账号的邮箱。

## 5. 成员变动

一个模板，八种事件，每种有自己的标题与事实：成员身份变动、恢复、月预算调整、离开 / 被移出、项目解散、
预算申请结果、Key 被轮换、Key 被管理员查看。事实里写项目、变化后的值和操作人；Key 事件眉行为 `SECURITY`。

## 6. 邀请跟进与预算预警（2026-10-14）

- **邀请明天过期**：发给被邀请人，到期前 24 小时一封；**邀请过期未接受**：发给发出邀请的人，到期时一封。
  两封都在发出（或重发）邀请时排进项目发件箱，接受、撤回、重发、解散时一起取消。
- **预算预警**（墨头层，与 Key 用量提醒同一模板）：成员本人在预警线和用完时各一封；能改这个人预算的人
  （普通成员：所有者 + 管理员；管理员：只有所有者）只在用完时一封；项目月上限只发所有者，预警线和用完各一封。
  每人每月每档一封，预算改动后重新计。细则见 `team-projects-2026-09.md`。
