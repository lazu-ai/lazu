# Paper States — 系统状态面

> **Locked:** 2026-09-01 · **整页修订:** 2026-09-29
> **Approved exploration:** 整页 = `lazu-ops:brand/explorations/error-pages-2026-09-a/index.html`（方向 A，衬线大数字）；卡片 = `lazu-ops:brand/explorations/error-pages-2026-09/index.html`
> **Decision:** 整页 = **状态标记 + 一句话**（2026-09-29 取代折角 / 封条 / 撕边）；可操作空态 = **虚线位**（Empty 1）；无操作空态 = **纯文字**；行内错误 = **断线**（Error 1）；加载 = **发丝线小圈**
> **Inherits:** `yunmu-console.md`（纸面、地面、墨/纸反转）、`color-system.md`（语义色只表达状态、只用小面积）
> **Supersedes:** `feedback-system.md` 中关于「错误空态图标框」的条款，见 §5

这是「用户没能看到他要的内容」时，页面该长什么样的唯一规范。覆盖 404、403、崩溃页、
功能未开启、一次性结果页（邀请、付款、被移出项目）、加载、空态、行内错误。

---

## 1. 两档原则

状态面的音量由**出现频率**决定，而不是由严重程度决定。

| 档       | 面                      | 频率       | 处理                                    |
| -------- | ----------------------- | ---------- | --------------------------------------- |
| **整页** | 404 / 403 / 崩溃 / 结果 | 一年几次   | 一枚状态标记 + 一句话，干净、能传达就够 |
| **卡片** | 加载 / 空态 / 行内错误  | 每天几十次 | 零装饰，只有排版和一个最小标记          |

高频面不配拥有值得看第二眼的东西。一枚图标在一个新工作区里会同屏重复出现八次，
那时它不再是图形，而是家具。这条原则优先于任何「让空状态更友好」的冲动。

## 2. 整页：状态标记 + 一句话

> 2026-09-29 修订。原「折角 / 封条 / 撕边」三种纸的遭遇已废止：在控制台里读作悬浮
> 弹窗，404 的幽灵行读作骨架屏，中文标题用展示衬线会回退成宋体。

所有整页状态共用 `StatusPage`（`apps/web/src/components/ui/status-page.tsx`），
居中，自上而下只有这几样：

| 部件         | 规则                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------- |
| **状态标记** | 有 HTTP 状态码就用码（`404` / `403`）；没有就用一个英文词，斜体。由墨到淡灰渐变，背后一团极淡的证据蓝光 |
| **标题**     | 说发生了什么。Geist 22px / 600，**不用展示衬线**                                                        |
| **一句话**   | 说原因或影响范围。不写用户没问的事（「没有数据被修改」「地址栏没有变化」）                              |
| **一枚胶囊** | 可选。帮读者对上号的那一条：访问的地址、交易号、项目名。等宽字                                          |
| **按钮**     | 最多两个，主按钮是最可能的下一步，用墨/纸反转的主按钮                                                   |
| **提示行**   | 可选。只在真的找到相近页面时出现「要找的是不是 X？」；猜错比不猜更糟                                    |

**状态标记是整页上唯一的展示衬线**（`--lazu-font-display`，80–120px）。这款字体只有
拉丁字形，所以标记只能是数字或英文词，中文一律在无衬线上。现行标记词表：

| 标记      | 面                                      |
| --------- | --------------------------------------- |
| `404`     | 页面不存在；邀请不存在；文档页不存在    |
| `403`     | 没有访问权限                            |
| `Error`   | 渲染崩溃（ErrorBoundary）；邀请读取失败 |
| `Off`     | 功能没有开启（模块开关、Studio）        |
| `Expired` | 邀请已过期                              |
| `Revoked` | 邀请已被撤回                            |
| `Joined`  | 已加入项目                              |
| `Paid`    | 付款已提交                              |
| `Unpaid`  | 付款没有完成                            |
| `Removed` | 已被移出项目                            |

新增整页状态从这张表里找最近的词；确实没有才加新词，一个词，英文，首字母大写。

**404 的「要找的是不是」**由 `lib/route-suggest.ts` 给出：候选只来自侧栏已知的控制台
路由（`CONSOLE_ROUTE_META`）和少数公开页；编辑距离 ≤ 2，或地址越过某个真实页面进入
不存在的子路径时，指回那个页面。文档站同理，候选来自文档侧栏（`apps/docs/components/docs-nav.ts`）。

崩溃页必须带 `role="alert"`（`live` 属性）：渲染崩溃不改变路由，没有任何其他机制会
告知辅助技术当前视图已被替换。崩溃页的次按钮是「复制错误信息」（错误、路由、时间）。
发版后旧标签页取不到已删除的代码分块时，ErrorBoundary 会先自动刷新一次进入新版本，
不显示崩溃页（`lib/stale-chunk.ts`，30 秒内最多一次）。

**等待不画整页。** 整页状态只表达结果；在得到结果之前，用 §3 的小圈，并遵守 300ms
延迟出现。

文档站 404（`apps/docs/components/not-found.tsx`）是同一个对象的文档版：替换 Vocs 自带
的 NotFound，nginx 对不存在的地址回真正的 404 状态码。

## 3. 加载：一枚小圈

15px 发丝线圆环（`--lazu-border-strong` 底，`--lazu-text-muted` 顶)+ 一行字，居中。
没有方框，没有进度条，没有骨架以外的第二种等待。

表格续载用同一个对象横排（`--inline`）。**全站只有这一种加载卡。**

路由级切换不用这张卡，用 `AppLoading` 的骨架屏：骨架管「整页在换」，小圈管
「面内在等」。

减弱动效下小圈**继续转动**——这是 `index.css` 既有的全局策略，一个停住的等待读起来
像一个失败的等待。

## 4. 空态：有动作才画虚线位

一个 1.5px 虚线框（14px 圆角，340px 上限宽），里面依次是标题、一句引导、第一步操作
的按钮。没有图标，没有插画。

虚线框在界面里天然读作「这里可以放东西」，于是空状态从道歉变成落点。

**虚线框不是控件，不给 hover 态**——给它 hover 背景等于声明了一个并不存在的点击
目标，coarse pointer 上还会点完粘住。只有框内的按钮响应指针。

**没有第一步操作时，不画虚线框。** 过滤无结果、只读图表没有数据等状态没有可投放的
目标；此时只显示标题与说明。一个不能完成的槽位会错误承诺这里可以添加内容。

标题写「还没有 X」而不是「没有 X」。

> 这不与 `feedback-system.md` §1「禁止虚线作为语义信号」冲突：那条禁的是用虚线
> 表达严重性（error / warning），这里的虚线表达的是容器状态（空），不承载语义色。

## 5. 行内错误：断线

一根发丝线在中间断开，断口一粒 5px `--lazu-danger` 圆点；下面是标题、说明、ghost
重试按钮，页脚 mono 行放 trace id。`role="alert"`。

这粒 5px 圆点是三张高频卡里**唯一**的语义色，符合 `color-system.md`「语义色只表达
状态、只用小面积」。

**本节取代 `feedback-system.md` 的以下条款**(该文档 2026-08-28 锁定时，状态卡还
是图标框流派）：

- §1.3「必要时的一枚软底徽记（仅错误空态的图标框）」——图标框已废除
- §4「软底 `--lazu-*-soft` 只用于两处：错误空态的图标框、`aria-invalid` focus
  ring」——现在只剩 focus ring 一处
- §5 度量表「错误空态图标框 40px,radius 12px,`*-soft` 底」——已删除

`feedback-system.md` 的其余部分（toast、InlineNotice、FieldMessage、语义色定义、
「纸面不变色」铁律）全部继续有效。

## 6. 失败与空白必须由组件区分

**加载失败用 `ErrorState`，不要用 `EmptyState` 加一个图标。** 空态不渲染图标（§4），
所以任何借图标区分失败与空白的写法都会退化成两个一模一样的面。区别应该由组件承担：
`ErrorState` 有断线标记、danger 点、`role="alert"` 和重试。

`EmptyState` 的 `icon` 属性为兼容旧调用点保留，但不再渲染；新代码不要传。

## 7. 新增状态面怎么办

维护页、超时、配额耗尽等新面，先按 §1 判定它属于哪一档，再从既有词汇里选：整页用
`StatusPage`，从 §2 的标记词表里挑一个语义最近的；卡片从小圈 / 虚线位 / 断线里挑。
**不要为一个新状态发明第四种卡片标记**，除非它在这三种里都找不到对应。

## 8. 支付单据（2026-09-24 修订）

历史双栏账号核对页已废止，探索稿仅保留作决策记录。Stripe 回跳、付款邮件和旧单据链接
都进入 `/console/wallet?top_up_id=…`：钱包在余额之上钉住那一笔的付款记录卡
（`components/ui/topup-record.tsx`），卡片用同一副骨架承担确认中 / 已到账 / 未付款三态，
只有未知的部分用占位与发丝线小圈等待；单据解析失败在卡内用通用 `InlineNotice` 提示
（2026-09-27 修订，取代此前独立的付款详情页）。
`/payment/document` 仅作兼容旧链接和打开 Stripe 单据的无界面跳转入口。
单据授权仍由服务端决定；查不到付款时不得断言一定是账号不匹配。
