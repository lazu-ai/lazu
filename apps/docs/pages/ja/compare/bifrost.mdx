# Lazu と Bifrost

[Bifrost](https://github.com/maximhq/bifrost) は、観測企業 Maxim AI の Go ゲートウェイで、20 を超えるプロバイダーへのアクセスを 1 つのエンドポイントに統合し、仮想キー、チーム、顧客、ドル建て予算を備えます。Lazu も Go ゲートウェイで、台帳、コンソール、ドキュメントサイトを備えた 1 つの製品として出荷されます。両者はこのサイトの中で形態が最も近い組み合わせです。違いは、誰がキーを持つか、そしてリクエストの記録が何のためにあるかです。事実は 2026 年 11 月 2 日に確認しました。

## それぞれ誰向けか

**Bifrost** は、ガバナンス付きの高速な Go ゲートウェイが欲しいプラットフォーム・インフラチーム向けです。チームや顧客にスコープされた仮想キー、リセット周期付きの予算、Prometheus メトリクスとトレース、MCP ゲートウェイ、そしてクラスターモード、ガードレール、SSO のための Enterprise 版です。

**Lazu** は、人とエージェントにキーを配るチーム、研究室、企業向けです。各キーに予算があり、各リクエストにキーの持ち主が読める記録が残り、運営者は設定ファイルではなくコンソールで上流、価格、ユーザーを管理します。

## 並べて見る

| | Bifrost | Lazu |
| --- | --- | --- |
| ランタイム | Web UI 付き Go ゲートウェイ。`npx`、Docker、Helm、Go SDK | Go ゲートウェイと worker、React コンソール、Vocs ドキュメント。1 つの Docker Compose スタック |
| 設定 | Web UI、`config.json`、または管理 API | 上流、価格、ユーザー、お知らせはコンソール。環境変数と `config.yaml` は認証情報のみ |
| アカウント | 仮想キー（`sk-bf-*`、プロバイダーはデフォルト拒否）、チーム、顧客 | ユーザー、チームとプロジェクト、メンバー予算、API キー |
| 予算 | 1 分から 1 年までのリセット周期付きドル建て予算。`402 budget_exceeded`。一時的な上乗せ | 前払い残高。キー別上限、プロジェクトと支出予算。呼び出し前に予約、プロバイダーのカウンターで精算、失敗時に解放 |
| 利用記録 | ログ、Prometheus メトリクス、分散トレース。予算ごとの現在の利用量 | リクエストごとに 1 件、利用量・計測元・課金明細付きで、送ったキーが読める。エージェントセッション。照合スクリプト |
| ルーティング | プロバイダーとモデル間のフェイルオーバー、キー間の負荷分散。適応型負荷分散は Enterprise | モデルごとに優先度と重みでチャネル選択、ヘルスウィンドウ、同一モデルでの再試行。公開の経路ヘルスページ |
| プロトコル | OpenAI、Anthropic、Google GenAI の SDK にそのまま差し替えられるベース URL。相互に変換 | 同じ 3 系統。無損失のときだけ変換し、それ以外は機能名を示す `400` |
| 拡張 | ミドルウェアアーキテクチャ。MCP ゲートウェイ | ビルドに組み込む Go と Web の拡張ポイント。コアは拡張の存在を知らない |
| 有料版 | Enterprise：クラスターモード、ガードレール、SAML/OIDC SSO、適応型負荷分散、MCP フェデレーテッド認証、SLA | なし。リポジトリにあるものはライセンスキーなしで全部動く |
| ライセンス | Apache-2.0 | AGPL-3.0-or-later |

## お金

どちらも呼び出し前にドル額を予約します。Bifrost は仮想キー、チーム、顧客ごとに予算を持ち、スケジュールでリセットし、`402 budget_exceeded` で拒否し、運営者が一時的な上乗せを追加できます。Lazu は前払い残高から引き落とします。上流を呼ぶ前に見積額を予約し、プロバイダーが報告した利用量で精算し、各次元をプロバイダー計測、ローカル推定、取得不能のいずれかとして記録します。課金対象の出力がない失敗は予約を返金し、アカウントが賄えないリクエストはプロバイダーに届かず、こっそり赤字になることはありません（[課金契約](https://github.com/lazu-ai/lazu/blob/main/docs/billing-contract.md)）。

違いは予算が誰のためのものかです。Bifrost の予算は社内の支出を管理し、リセットされます。Lazu の予算は払い込まれた残高の上にあり、各リクエストの記録は運営者だけでなく、それを使った人やエージェントが読めます。

## プロトコル

どちらも OpenAI、Anthropic、Gemini のリクエストを受け付け、別形式を話すプロバイダーに送ります。Bifrost はプロバイダー間のリクエスト変換、レスポンス正規化、エラーマッピングを文書化していますが、忠実性の規則は示していません。Lazu は無損失と検証されたエッジに沿ってのみ変換し、それ以外は上流を呼ぶ前に機能とフィールドを示す `400` で拒否するので、ツール呼び出しや推論パラメーターが途中で落とされることはありません（[設計ノート](https://github.com/lazu-ai/lazu/blob/main/docs/protocol-conversion-architecture.md)）。

## Bifrost にあって Lazu にないもの

- MCP ゲートウェイ、Enterprise ではフェデレーテッド認証付きの MCP。
- 標準で付く Prometheus メトリクスと分散トレース。
- ゲートウェイをライブラリとして使う Go SDK、Helm チャート、`npx` での起動。
- 予算のリセット周期と一時的な上乗せ。
- 寛容な Apache-2.0 ライセンス。

## どちらを選ぶか

- ゲートウェイが自社サービスのためのインフラで、既存スタックにメトリクスとトレースが欲しい、または Apache-2.0 が必要なら **Bifrost**。
- ゲートウェイが人に渡すアカウントそのもので、予算付きキー、残高、持ち主が読めるリクエスト記録、プログラマーでない運営者が扱えるコンソールが要るなら **Lazu**。
