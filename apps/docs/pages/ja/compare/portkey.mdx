# Lazu と Portkey

[Portkey AI Gateway](https://github.com/Portkey-AI/gateway) は、非常に多数のモデルへルーティングする TypeScript ゲートウェイで、再試行、フォールバック、負荷分散、ガードレールをリクエストごとに設定します。キー、予算、RBAC、観測は Portkey のホスト型プラットフォームに属します。Lazu は、アカウント、台帳、コンソールを自ら携える Go ゲートウェイです。事実は 2026 年 11 月 2 日に確認しました。

## Portkey の現在地

オープンソースリポジトリの最終リリースは 2026 年 1 月の `v1.15.2`、最終コミットは 2026 年 5 月です。`2.0.0` ブランチは存在しますがマージされていません。Palo Alto Networks は 2026 年 5 月 29 日に Portkey の買収を完了しました。ゲートウェイは今も動きますが、今日これを選ぶ人は、将来が別の場所で決められるコードベースを選ぶことになります。

## それぞれ誰向けか

**Portkey** は、多数のモデルを呼び、再試行、フォールバック、重み付き負荷分散、ガードレールを各リクエストの設定オブジェクトとして表現したいアプリケーション開発者向けです。ローカルコンソールを超えるキー、予算、ログのすべてについて、ホスト型プラットフォームを使うことを受け入れられる人です。

**Lazu** は、人とエージェントにキーを配り、アカウント層を自分のサーバーに置きたいチーム、研究室、企業向けです。呼び出し前に予約される予算、キーの持ち主が読めるリクエストごとの利用記録、価格付きカタログ、運営者のためのコンソールです。

## 並べて見る

| | Portkey Gateway | Lazu |
| --- | --- | --- |
| ランタイム | TypeScript。`npx`、Docker、Node、Cloudflare Workers | Go ゲートウェイと worker、React コンソール、Vocs ドキュメント。1 つの Docker Compose スタック |
| 設定 | リクエストごとの設定オブジェクトまたはヘッダー：再試行、フォールバック、負荷分散、ガードレール | 上流、価格、ユーザー、お知らせはコンソール |
| アカウント | ホスト型プラットフォームの仮想キー。オープンソースのゲートウェイにはキーストアの記載なし | ユーザー、チームとプロジェクト、メンバー予算、API キー |
| 予算 | キーを失効させるコスト・トークン上限、アラートとリセット付き。ホスト型 Enterprise プランと一部の Pro 顧客 | 前払い残高。キー別上限、プロジェクトと支出予算。呼び出し前に予約、プロバイダーのカウンターで精算、失敗時に解放 |
| 利用記録 | ローカルコンソールにローカルログ。ログ、トレース、保持はホスト型プランの機能（Dev は 3 日、Pro は 30 日） | リクエストごとに 1 件、利用量・計測元・課金明細付きで、送ったキーが読める。エージェントセッション。照合スクリプト |
| ルーティング | エラートリガー付きフォールバック、バックオフ付き最大 5 回の再試行、重み付き・条件付きルーティング | モデルごとに優先度と重みでチャネル選択、ヘルスウィンドウ、同一モデルでの再試行。公開の経路ヘルスページ |
| プロトコル | プロバイダー横断の OpenAI シグネチャ | OpenAI、Anthropic Messages、Gemini をネイティブに。無損失のときだけ変換 |
| 拡張 | ガードレール連携の `plugins/` | ビルドに組み込む Go と Web の拡張ポイント |
| 有料版 | Dev（無料）、Pro、Enterprise：キャッシュ、プロンプト管理、観測、予算、PII 秘匿、RBAC、SSO、プライベートデプロイ | なし |
| ライセンス | MIT。リポジトリは 2026 年 5 月以降更新なし | AGPL-3.0-or-later |

## お金

Portkey では予算はホスト型プラットフォームの機能です。プロバイダー連携にかけるコストまたはトークンの上限で、達するとキーを失効させ、アラートのしきい値と週次または月次のリセットを持ち、Enterprise と一部の Pro 顧客が使えます。オープンソースのゲートウェイ単体に予算はありません。Lazu では予算はセルフホスト製品の一部です。上流を呼ぶ前に前払い残高から見積額を予約し、プロバイダーが報告した利用量で精算し、各次元をプロバイダー計測、ローカル推定、取得不能のいずれかとして記録し、課金対象の出力がない失敗は予約を返金します（[課金契約](https://github.com/lazu-ai/lazu/blob/main/docs/billing-contract.md)）。

## プロトコル

Portkey の README は、プロバイダー横断で使い慣れた OpenAI シグネチャだと述べています。Lazu は OpenAI、Anthropic Messages、Gemini のリクエストをネイティブに受け付け、無損失と検証されたエッジに沿ってのみ変換します。上流が運べない機能を必要とするリクエストは、上流を呼ぶ前に機能名を示す `400` で拒否します（[設計ノート](https://github.com/lazu-ai/lazu/blob/main/docs/protocol-conversion-architecture.md)）。

## Portkey にあって Lazu にないもの

- 千を優に超えるモデルとモダリティへの対応。
- 条件付きルーティングや設定可能なフォールバックトリガーを含む、リクエスト単位で表現するルーティング。
- サードパーティベンダーによる一連のガードレールプラグイン。
- Cloudflare Workers へのデプロイ。

## どちらを選ぶか

- アプリケーション開発者で、ルーティングポリシーをリクエスト自体に持たせたく、キー、予算、ログはホスト型プラットフォームで構わないなら **Portkey**。ただしリポジトリについて上記の注意があります。
- アカウント層を自分のサーバーに置き、予算、残高、キーの持ち主が読める利用記録が要るなら **Lazu**。
