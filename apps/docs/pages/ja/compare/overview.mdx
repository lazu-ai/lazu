# Lazu と他の LLM ゲートウェイの比較

このページの各プロジェクトは、複数のモデルプロバイダーの前に 1 つのエンドポイントを置くものです。違いは、誰のために作られているか、そしてお金をどう扱うかにあります。ここでは各プロジェクトが何のためのものかを述べるだけで、順位は付けません。事実は 2026 年 11 月 2 日に各プロジェクトのリポジトリとドキュメントで確認したもので、今後ずれていきます。

## Lazu は何のためのものか

Lazu はチーム、研究室、企業のための**モデルアカウント**です。人とエージェントの一人ひとりが自分の予算を持つキーを受け取り、すべてのリクエストが利用記録を残し、キーの持ち主がそれを読み返せます。ゲートウェイ、台帳、コンソール、このドキュメントサイトが 1 つのデプロイ可能な製品としてまとまり、AGPL-3.0 で公開されています。[New API](/ja/compare/new-api) から派生し、New API は one-api から派生しています。ルーティング、課金、利用記録の 3 層は、文書化された契約に沿って書き直されました。

答えたい問いが「誰がどのモデルにいくら使ったか、それを証明できるか」なら Lazu を選んでください。自分のサービスに組み込むライブラリ、サーバーを運用しないホスト型のキー、すでに運用しているゲートウェイ用のプラグインが必要なら、別のものを選んでください。

## 予算を使い切るとどうなるか

予算の価値は、リクエストを止めるその瞬間で決まります。原則は共通で、仕組みが違います。

- **Lazu** は上流を呼ぶ前に前払い残高から資金を予約し、呼んだ後にプロバイダー自身の利用カウンターで精算します。キー、プロジェクト、アカウントが賄えないリクエストは、プロバイダーに届く前に拒否されます。課金対象の出力がない失敗は予約を解放します。プロバイダーがカウンターを返さなかった場合は記録にそう書かれます。数字を作らず、こっそり赤字にもしません（[課金](/ja/billing)、[課金契約](https://github.com/lazu-ai/lazu/blob/main/docs/billing-contract.md)）。
- **LiteLLM** はキー、ユーザー、チーム、顧客が `max_budget` を超えるとブロックし、周期的にリセットできます。予算の事前警告は Enterprise です。
- **New API** と **one-api** はトークンまたはユーザーの枠が尽きると `403 insufficient_user_quota` を返します。
- **Bifrost** は `402 budget_exceeded` を返し、一時的な上乗せができます。
- **Kong** はコスト上限を超えたリクエストの*次の*リクエストをブロックします。
- **Portkey** はホスト型 Enterprise プランでキーを失効させ、**Helicone** は時間窓ごとに金額でレート制限しますがキー予算はありません。

## リクエストが残すもの

Lazu は完了した各リクエストについて、正規化されたトークン次元、そのうちプロバイダーが計測したものとローカルで推定したもの、課金明細、公開タイミングを保存し、リクエストを送ったキーがリクエスト ID で取り出せます（[リクエスト詳細](/ja/endpoints/usage-requests)）。コーディングエージェントからのリクエストはセッションにまとめられ、リポジトリには、プロンプトを出力せずにエクスポートしたセッションを照合する[スクリプト](https://github.com/lazu-ai/lazu/blob/main/ops/scripts/summarize-agent-session.py)が同梱されています。他のプロジェクトもリクエストとコストを記録します。違いは、Lazu の記録が文書化された契約の一部であり、運営者だけでなく支払った本人が読めることです。

## プロトコル

Lazu、LiteLLM、New API、Bifrost は OpenAI、Anthropic Messages、Gemini のリクエストをネイティブに受け付け、プロバイダーが別の形式を話す場合は変換します。one-api は OpenAI 形式のみです。Kong のオープンソース `ai-proxy` は OpenAI 形式から変換するか、ネイティブ形式をそのまま通します。Lazu には他が明言しない規則が 1 つあります。変換は無損失のときだけ行い、上流が運べない機能を必要とするリクエストは、上流を呼ぶ前に機能名を示す `400` で拒否します（[設計ノート](https://github.com/lazu-ai/lazu/blob/main/docs/protocol-conversion-architecture.md)）。

## 新しいプロジェクト

2025〜2026 年に登場したセルフホスト可能なゲートウェイで知っておく価値があるものが 3 つあります。**gpt-load**（Go、MIT。1 つの管理キーの背後にチャネルグループとキープール、個人別アカウントはなし）、**AxonHub**（Go。任意の SDK から任意のプロバイダーへ、リクエスト別コスト追跡、RBAC）、mozilla-ai の **otari**（Python。仮想キー、予算、利用追跡）。このページでは README 以上は確認していません。
