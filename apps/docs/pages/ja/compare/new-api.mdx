# Lazu と New API

Lazu は [New API](https://github.com/QuantumNous/new-api) をベースにし、New API は [one-api](https://github.com/songquanpeng/one-api) をベースにしています。この系譜は上流のライセンス条件に従い、リポジトリの NOTICE とコンソールに残されています。このページは何が変わったかについてであり、どちらが優れているかではありません。New API はよく運営され大きなコミュニティを持つプロジェクトで、すでに運用している人は、以下の違いが重要でない限り移行する理由はありません。事実は 2026 年 11 月 2 日に確認しました。

## 共通の土台

どちらも Web コンソール付きの Go ゲートウェイです。どちらも OpenAI Chat Completions と Responses、Anthropic Messages、Gemini `generateContent` のリクエストを受け付け、優先度と重みを持つ上流チャネルを保持し、失敗時に再試行し、ユーザー、グループ、枠付き API キーを管理し、前払い残高で課金します。どちらも Docker Compose で PostgreSQL と Redis とともに動きます。片方のコンソールを知っていれば、もう片方も見慣れたものです。

## Lazu が書き直したもの

**課金は倍率ではなく契約。** New API は倍率と式ベースの価格設定を使い、トークンまたはユーザーの枠が尽きると `403 insufficient_user_quota` で止めます。Lazu は課金経路を文書化された[課金契約](https://github.com/lazu-ai/lazu/blob/main/docs/billing-contract.md)に置き換えました。呼び出し前に資金を予約し、プロバイダーの利用カウンターで精算し、課金対象の出力なしに失敗したリクエストは解放します。各利用次元は、プロバイダーが計測したか、Lazu が推定したか、取得不能かを記録します。取得不能な数値を予約額で埋めることはなく、アカウントがこっそり赤字になることもありません。価格はキーが照会できるカタログに、モデル別・レーン別に掲載されます。

**顧客が読める利用記録。** New API は運営者向けに利用・監査ログを保持します。Lazu は完了した各リクエストを、それを送ったキーに公開します。正規化された利用量、計測元、課金明細、タイミングをリクエスト ID で取得できます（[リクエスト詳細](/ja/endpoints/usage-requests)）。コーディングエージェントのリクエストはセッションにまとめられ、[スクリプト](https://github.com/lazu-ai/lazu/blob/main/ops/scripts/summarize-agent-session.py)がエクスポートしたセッションをオフラインで照合します。

**忠実性ルール付きのプロトコル変換。** New API は受信形式とプロバイダー形式の間で変換します。Lazu はこれを不変のリクエスト表現の上に作り直しました。各試行は元のリクエストから経路を計画し直し、変換は無損失と検証されたエッジに沿ってのみ行い、上流が運べない機能を必要とするリクエストは呼び出し前に機能名を示す `400` で拒否します（[設計ノート](https://github.com/lazu-ai/lazu/blob/main/docs/protocol-conversion-architecture.md)）。

**見えるルーティング。** 優先度と重みによるチャネル選択、再試行、障害のあるチャネルをローテーションから外すことは共通です。Lazu はクライアントエラーをチャネル障害として数えず、経路ヘルスページを公開して、ユーザーが運営者に聞かずに各経路の状態を見られるようにしました。

**チームとプロジェクト。** New API にはユーザーとグループがあります。Lazu はメンバー、ロール、招待、メンバー別予算を持つプロジェクトを追加し、1 つの組織が 1 つの残高で複数のチームを運用できます。

**拡張ポイント。** デプロイ側が組み込む機能は文書化されたフックで接続します（[docs/EXTENSIONS.md](https://github.com/lazu-ai/lazu/blob/main/docs/EXTENSIONS.md)）。コアはそれらなしでビルドでき動作します。New API はメディアタスク向けの JavaScript タスクプラグインで拡張し、それ以外はソース変更で対応します。

**ゲートウェイだけでない製品。** Lazu は公開ページ、レーンと価格付きのモデルカタログ、英語・簡体字中国語・繁体字中国語・日本語のドキュメントサイトを同梱し、1 つのソースから生成され、ドキュメントを読むエージェント向けの Markdown と `llms.txt` を備えます。

## New API にあって Lazu にないもの

- より大きなコミュニティ、より多くのチャネル種別、新プロバイダーへのより速い対応。
- サブスクリプションと引換コード、Stripe 以外の決済連携。
- 1Panel と宝塔のインストーラー、マルチノードクラスターのドキュメント。

## 並べて見る

| | New API | Lazu |
| --- | --- | --- |
| ベース | one-api | New API |
| ライセンス | AGPL-3.0 + 表示条件 | AGPL-3.0-or-later。New API と one-api の表示を維持 |
| 課金 | 倍率と式。枠切れで `403` | 予約 → 精算 → 解放、次元別の計測元、モデル別・レーン別価格 |
| 利用記録 | 運営者ログ | キーが読めるリクエスト別記録。エージェントセッション。照合スクリプト |
| プロトコル変換 | 受信形式をプロバイダー形式へ | 無損失エッジのみ。それ以外は機能名を示す `400` |
| ルーティング | 優先度、重み、再試行、アフィニティ | 同じ。加えて公開の経路ヘルスページ |
| 組織 | ユーザーとグループ | ユーザー、チーム、メンバー予算付きプロジェクト |
| 拡張 | JavaScript タスクプラグイン。ソース変更 | Go と Web の拡張ポイント |
| ドキュメント | docs.newapi.pro | lazu.ai/docs の 4 言語、`llms.txt` 付き |

## どちらを動かすか

すでに New API を動かしている、サブスクリプションや引換コードの機能が必要、プロバイダーの公開直後に最も広いチャネル対応が欲しい、なら **New API** を。

売るもの、配るものがアカウントである、つまり呼び出し前に予約される予算、顧客が読める記録、価格付きカタログ、公開の経路ページが要るなら **Lazu** を。
