# Lazu と One API

[one-api](https://github.com/songquanpeng/one-api) はこの系統を始めたプロジェクトです。多数のプロバイダーの前に OpenAI 形式のエンドポイントを 1 つ置き、ユーザー、トークン、枠を Web コンソールで管理します。[New API](/ja/compare/new-api) はそこから派生し、Lazu は New API から派生しました。その表示は Lazu の NOTICE とコンソールに残されています。このページは one-api が何であり Lazu が何を変えたかについてであり、どちらが優れているかではありません。事実は 2026 年 11 月 2 日に確認しました。

## one-api の現在地

one-api は MIT ライセンスで、README にフッターの表示とリンクを維持する条件があります。最終リリース `v0.6.10` は 2025 年 2 月、最終コミットは 2026 年 1 月です。今も動作し、多くのデプロイが運用していますが、1 年以上リリースのないプロジェクトは、プロバイダーの新しいモデル、エンドポイント、リクエストフィールドには追随しません。それが派生プロジェクトを見る主な理由です。

## それぞれ誰向けか

**one-api** は、OpenAI 形式のエンドポイントが 1 つ、チャネルが数本、そして枠・有効期限・IP 範囲・許可モデル付きのトークンを、メール、GitHub、Feishu、WeChat でサインインするユーザーに配りたいセルフホスト派向けです。引換コードでユーザーの枠をチャージします。

**Lazu** は、人とエージェントにモデルアカウントを与えるチーム、研究室、企業向けです。予算付きのキー、キーの持ち主が読めるリクエストごとの利用記録、価格と経路ヘルス付きのカタログ。OpenAI に加えて Anthropic と Gemini のリクエストもネイティブに受け付けます。

## お金

one-api はトークンの枠を先に消費し、応答後に調整し、ユーザーまたはトークンの枠が尽きると `403` で拒否します。Lazu は先消費の考え方を残し、契約として文書化しました。上流を呼ぶ前に前払い残高から見積額を予約し、プロバイダーが報告した利用量で精算し、各次元をプロバイダー計測、ローカル推定、取得不能のいずれかとして記録します。課金対象の出力がない失敗は予約を返金し、アカウントが賄えないリクエストはプロバイダーに届かず、取得不能な数値を予約額で埋めることはありません（[課金契約](https://github.com/lazu-ai/lazu/blob/main/docs/billing-contract.md)）。

## プロトコル

one-api は OpenAI 形式のリクエストを受け付け、各チャネル種別に変換します。Claude Code や Gemini SDK のユーザーは OpenAI 互換アダプターを経由する必要があります。Lazu は 3 系統すべてをネイティブに受け付け、無損失と検証されたエッジに沿ってのみ変換します。上流が運べない機能を必要とするリクエストは、上流を呼ぶ前に機能名を示す `400` で拒否します（[設計ノート](https://github.com/lazu-ai/lazu/blob/main/docs/protocol-conversion-architecture.md)）。

## one-api にあって Lazu にないもの

- Feishu と WeChat でのサインイン、コンソールのテーマ。
- 引換コード。
- 単一のリリースバイナリと、Sealos、Zeabur、Render のワンクリックテンプレート。
- マスター/スレーブのマルチノードデプロイのドキュメント。

## どちらを動かすか

すでに one-api で用が足りていて、one-api が知っているモデルに対する OpenAI 形式のクライアントだけが必要なら **one-api** を。

同じ形のコンソールを活発なリリースとともに使いたい、Anthropic と Gemini のネイティブエンドポイント、呼び出し前に予約される予算、キーの持ち主が読める利用記録が要るなら **Lazu** を。one-api から移行するなら、[New API](/ja/compare/new-api) がもう 1 つの保守されている派生プロジェクトで、そのページに両者の違いが書かれています。
