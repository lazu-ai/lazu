# Lazu と OpenRouter

[OpenRouter](https://openrouter.ai) は、プロバイダー横断の数百のモデルに対する API キーを 1 つ与え、プロバイダーがエラーを返せば自動でフォールバックし、動かすものは何もありません。クローズドなホスト型サービスで、リポジトリもセルフホストの選択肢もありません。Lazu は AGPL-3.0 のオープンソースで、自分のサーバーで動きます。lazu.ai はモデル込みのホスト型サービスとしても運用しています。このページはそれぞれが何であるかについてであり、どちらが安いかではありません。事実は 2026 年 11 月 2 日に確認しました。

## それぞれ誰向けか

**OpenRouter** は、キー 1 つと請求 1 つで多数のモデルを試したり出荷したりしたく、キー、ログ、残高が第三者のところにあって構わない開発者向けです。

**Lazu** は、キーを発行する側になりたいチーム、研究室、企業向けです。すべての人とエージェントに予算付きのキー、キーの持ち主が読めるリクエストごとの利用記録、自分で決めた価格のカタログ、自分のプロバイダーアカウントへの経路。セルフホストするか、動かしたくなければホスト型の lazu.ai を使います。

## 並べて見る

| | OpenRouter | Lazu |
| --- | --- | --- |
| 形態 | ホスト型サービス | 自分で動かすオープンソースのゲートウェイ。lazu.ai でホスト型も |
| ソース | クローズド | GitHub 上の AGPL-3.0-or-later |
| プロバイダー | OpenRouter 自身のプロバイダー契約、数百のモデル | 自分のプロバイダーアカウント、または lazu.ai のもの |
| プロトコル | OpenAI 風の Chat Completions、Responses、Completions。Anthropic Messages | OpenAI Chat Completions と Responses、Anthropic Messages、Gemini `generateContent` |
| キー | 管理 API から発行するキー、クレジット上限と任意の日次リセット付き。キー別の利用量 | ユーザー、チームとプロジェクト、メンバー予算、API キー |
| 予算 | キーごとのクレジット上限 | 前払い残高。キー別上限、プロジェクトと支出予算。呼び出し前に予約、プロバイダーのカウンターで精算、失敗時に解放 |
| 利用記録 | モデル、プロバイダー、キーで絞り込めるアクティビティページ。コストとトークンを返すリクエスト別の generation エンドポイント | リクエストごとに 1 件、利用量・計測元・課金明細付きで、送ったキーが読める。エージェントセッション。照合スクリプト |
| ルーティング | エラー時に次のプロバイダーへ自動フォールバック。速度や価格を優先するモデルバリアント | モデルごとに優先度と重みでチャネル選択、ヘルスウィンドウ、同一モデルでの再試行。公開の経路ヘルスページ |
| 価格 | プロバイダーの定価 + クレジット購入時のプラットフォーム手数料 | 自分のカタログでモデル別・レーン別に設定する価格 |
| チーム | Business と Enterprise プラン | メンバー、ロール、招待、メンバー予算を持つチームとプロジェクト。オープンソース製品に含まれる |

## お金

OpenRouter はクレジットを売ります。推論はプロバイダーの定価にクレジット購入ごとのプラットフォーム手数料を加えた額で、発行キーごとにクレジット上限があります。Lazu は、あなたがチャージし価格を決める前払い残高を預かります。上流を呼ぶ前に見積額を予約し、プロバイダーが報告した利用量で精算し、各次元をプロバイダー計測、ローカル推定、取得不能のいずれかとして記録し、アカウントが賄えないリクエストはプロバイダーに届きません（[課金契約](https://github.com/lazu-ai/lazu/blob/main/docs/billing-contract.md)）。セルフホストの Lazu では上流の請求はあなたのものなので、モデルごとに設定した価格がそのまま、あなたの人たちが払う価格になります。

## リクエストが残すもの

どちらもリクエスト別のコストを公開します。OpenRouter の generation エンドポイントはリクエスト ID に対するトークンとコストを返します。Lazu の[リクエスト詳細](/ja/endpoints/usage-requests)はそれに加えて、プロバイダーが計測した数値と推定された数値の区別、課金明細の項目、公開タイミングを返し、コーディングエージェントのリクエストをセッションにまとめ、[スクリプト](https://github.com/lazu-ai/lazu/blob/main/ops/scripts/summarize-agent-session.py)がオフラインで照合します。

## OpenRouter にあって Lazu にないもの

- 多数のプロバイダーの数百のモデルがキー 1 つの背後にあり、開くべきプロバイダーアカウントがない。
- 動かすもの、運用するものが何もない。
- 同じモデルのプロバイダー横断フォールバックと、速度や価格を優先するバリアント。
- 月間ボリュームまで手数料が免除される Bring-your-own-key。

## どちらを選ぶか

- 開発者 1 人または小さなアプリで、今日いちばん広いモデルリストが欲しく、他人にキーを発行する必要がないなら **OpenRouter**。
- 人とエージェントにキーを発行し、予算と記録を自分の条件で持ち、自分で動かす選択肢が欲しいなら **Lazu**。動かすことが障害なら、lazu.ai は同じ製品のホスト型です。
