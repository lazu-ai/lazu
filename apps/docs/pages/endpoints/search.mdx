## What it returns

<EndpointGrid>
  <EndpointTile title="Normalized results">
    Every backend maps into <code>title</code>, <code>url</code>,
    <code>snippet</code>, optional <code>content</code>,
    <code>published_at</code>, <code>score</code> and <code>source</code>.
  </EndpointTile>

    store the same routing metadata for support and billing reconciliation.
  </EndpointTile>

## Hosted configuration

The `/v1/search` implementation supports Tavily, Serper, Exa, Jina and Brave,
but the hosted Lazu deployment is configured with this active set:

| Backend     | Hosted status | Capabilities                        | Notes                                                                 |
| ----------- | ------------- | ----------------------------------- | --------------------------------------------------------------------- |
| Tavily      | Enabled       | `web_search`, `web_fetch`, `answer` | Supports `include_answer` and `search_depth`; `advanced` is 2 units.  |
| Serper      | Enabled       | `web_search`                        | Maps `country` / `region`, `language` and `time_range` when provided. |
| Jina        | Enabled       | `web_search`, `web_fetch`           | Uses `https://s.jina.ai`; best for retrieval-style snippets.          |
| Exa / Brave | Supported     | `web_search` after operator setup   | Available for self-hosted or admin-configured deployments.            |

Hosted backends currently use the default backend policy: up to 10 results per
request and an 8s upstream timeout. If you send a larger `max_results`, Lazu
clips it to the selected backend policy.

## Request body

<FieldList>
  <Field name="query" type="string" required>
    Search query. The MVP supports one query per request.
  </Field>
  <Field name="type" type="string" nullable values={["web", "news"]}>
    Search vertical. Defaults to <code>web</code>.
  </Field>
  <Field name="backend" type="string" nullable>
    <code>auto</code>, a provider name such as <code>tavily</code> or{" "}
    <code>serper</code>, or a configured backend ID/name. Defaults to{" "}
    <code>auto</code>.
  </Field>
  <Field name="region" type="string" nullable>
    Region hint. Serper maps this to <code>gl</code>; other providers may ignore
    unsupported regions.
  </Field>
  <Field name="language" type="string" nullable>
    Language hint such as <code>en</code> or <code>zh-CN</code>.
  </Field>
  <Field
    name="time_range"
    type="string"
    nullable
    values={["day", "week", "month", "year"]}
  >
    Freshness hint. Providers that cannot map the value may ignore it.
  </Field>
  <Field name="max_results" type="integer" nullable>
    Number of results to return. Defaults to <code>10</code> and is capped by
    the selected backend policy.
  </Field>
  <Field
    name="search_depth"
    type="string"
    nullable
    values={["basic", "advanced"]}
  >
    Provider depth hint. Tavily <code>advanced</code> uses two billable credits.
  </Field>
  <Field name="include_answer" type="boolean" nullable>
    Include a provider answer when the selected backend returns one. Lazu does
    not generate its own final answer in this endpoint.
  </Field>
  <Field name="include_raw_content" type="boolean" nullable>
    Include raw or cleaned content when the provider returns it. Defaults to
    <code>false</code>.
  </Field>
  <Field name="include_domains" type="string[]" nullable>
    Restrict results to domains. Token-level domain allowlists still apply.
  </Field>
  <Field name="exclude_domains" type="string[]" nullable>
    Exclude domains when supported by the selected backend.
  </Field>
  <Field name="include_provider_payload" type="boolean" nullable>
    Return the provider-native payload for debugging. Defaults to
    <code>false</code>.
  </Field>
  <Field name="provider_options" type="object" nullable>
    Advanced provider passthrough. Only the selected provider's object is used,
    for example <code>{'{"serper":{"tbs":"qdr:d"}}'}</code>.
  </Field>
</FieldList>

## Billing

Search backends are priced from their configured <code>search_price</code>.
The value is the USD price per provider billing unit, not always per HTTP
request.

Check the currently displayed search price and reconcile the `web_search` line item in request details. Do not infer a free service from an old example or deployment configuration.

| Backend | Unit mapping                                                     |
| ------- | ---------------------------------------------------------------- |
| Tavily  | <code>basic</code> = 1 credit; <code>advanced</code> = 2 credits |
| Serper  | 1 successful query = 1 unit                                      |
| Jina    | 1 successful query = 1 unit                                      |

Failed upstream calls, timeouts and invalid requests are refunded according to
the normal Lazu billing rules.
